# constants.yml key ownership

Every key in `resources/data/constants.yml` is owned by exactly one of:

- **T1** — `kawari-constants-gen`: derived from live EXD data and auto-regenerated by
  `tools/constants-gen`. These are the ONLY keys that tool may write.
- **T2/D** — client-fixed: sizes are fixed by FFXIVClientStructs `PlayerState` arrays (or otherwise
  not a clean single-sheet derivation). They exceed the current data and must NOT be auto-generated.
- **other** — unrelated constants (versions, opcodes, positions, obfuscation tables) owned by their
  respective tooling, not by the size generators.

The partition is asserted in code: `owned_keys_present_and_disjoint_from_client_fixed`
(`tools/constants-gen/src/main.rs`) checks that all 18 T1 keys are present in `constants.yml` and
disjoint from the client-fixed set.

| AETHERYTE_UNLOCK_BITMASK_SIZE | Aetheryte | Count | Div8 |
| ADVENTURE_BITMASK_SIZE | Adventure | Count | Div8 |
| CHOCOBO_TAXI_STANDS_BITMASK_SIZE | ChocoboTaxiStand | Count | Div8 |
| BUDDY_EQUIP_BITMASK_SIZE | BuddyEquip | Count | Div8 |
| BEAST_TRIBE_ARRAY_SIZE | BeastTribe | CountMinus1 | Raw |
| MOUNT_BITMASK_SIZE | Mount | IndexField(Order) | Div8 |
| CUTSCENE_SEEN_BITMASK_SIZE | CutsceneWorkIndex | IndexField(WorkIndex) | Div8 |
| CAUGHT_FISH_BITMASK_SIZE | FishParameter | IndexRowIdWhere(IsInLog) | Div8 |
| CAUGHT_SPEARFISH_BITMASK_SIZE | SpearfishingItem | RowIdMinusOffset(20000) | Div8 |
| AETHER_CURRENT_COMP_FLG_SET_BITMASK_SIZE | AetherCurrentCompFlgSet | PopulatedRowIdPlus1 | Div8 |

Rules: `Count` = max_row_id+1. `CountMinus1` = max_row_id (drops the empty row-0 header).
`IndexField(f)` = max(row.f)+1. `IndexRowIdWhere(b)` = max(row_id where row.b)+1.
`RowIdMinusOffset(k)` = max(row_id in [k,k+10000)) − k (no +1: the top block rows are empty
sentinels). `PopulatedRowIdPlus1` = max(row_id where the row is populated) + 1 (drops the trailing
all-zero row). Unit: `Div8` = ceil(N/8), `Raw` = N.

## T2/D — client-fixed (NOT auto-generated)

These look stale against current data but are intentionally fixed (larger than the data, or no clean
single-sheet mapping). The three called out by the design as "stale-looking but client-fixed" are the
first three:

- GATHERED_GATHERING_ITEMS_BITMASK_SIZE
- UNLOCKED_FISHING_SPOTS_BITMASK_SIZE
- CLASSJOB_ARRAY_SIZE
- ACTIVE_HELP_BITMASK_SIZE
