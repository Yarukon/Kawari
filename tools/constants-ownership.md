# constants.yml key ownership

Every key in `resources/data/constants.yml` is owned by exactly one of:

- **T1** — `kawari-constants-gen`: derived from live EXD data and auto-regenerated by
  `tools/constants-gen`. These are the ONLY keys that tool may write.
- **T2** — `extract_client_constants.py`: client-fixed sizes read straight from the client's own
  `IsXxxUnlocked`-family range guards by the IDA tool `tools/extract_client_constants.py`. These are
  fixed by FFXIVClientStructs `PlayerState`/`QuestManager` arrays (larger than the current data), so
  they are NOT EXD-derivable, but the client hardcodes the bound so the IDA tool can extract it.
- **D** — manual client-fixed: fixed by the client with no inline bound the IDA tool can key off
  (red-black trees, global byte arrays via a shared helper, content arrays indexed by id−offset).
  Maintained by hand.
- **other** — unrelated constants (versions, opcodes, positions, obfuscation tables) owned by their
  respective tooling, not by the size generators.

The partition is asserted in code: `owned_keys_present_and_disjoint_from_client_fixed`
(`tools/constants-gen/src/main.rs`) checks that all 23 T1 keys are present in `constants.yml` and
disjoint from the client-fixed set (the T2 + D keys). T1 ∩ (T2 ∪ D) = ∅.

Rules: `Count` = max_row_id+1. `CountMinus1` = max_row_id (drops the empty row-0 header).
`IndexField(f)` = max(row.f)+1. `IndexRowIdWhere(b)` = max(row_id where row.b)+1.

sentinels). `PopulatedRowIdPlus1` = max(row_id where the row is populated) + 1 (drops the trailing
all-zero row). Unit: `Div8` = ceil(N/8), `Raw` = N.

## T2 — extract_client_constants.py (11 keys)

Client-fixed sizes with a clean inline bound in an `IsXxxUnlocked`-family guard. The IDA tool matches
a byte pattern per function (symbol-independent, so it runs on int OR CN builds), reads the bound
immediate, and converts it to a byte size via `unit`. Pattern data lives in
`tools/client_constants_patterns.json`; regenerate it with `T2_MODE=gen-patterns` on the renamed
int-client IDB. `unit`: `bit` = ceil(K/8) (guard tests the raw bit index), `byte` = K (guard tests
index>>3), `byte_masked` = K/8 (guard tests index & ~7).

| key | client fn | unit |
|---|---|---|
| COMPLETED_QUEST_BITMASK_SIZE | QuestManager.IsQuestComplete1 | byte |
| COMPLETED_RECIPES_BITMASK_SIZE | QuestManager.IsRecipeComplete | byte |
| UNLOCKED_MAP_MARKERS_BITMASK_SIZE | QuestManager.IsMapMarkerUnlocked | byte |
| GATHERED_GATHERING_ITEMS_BITMASK_SIZE | QuestManager.IsGatheringItemGathered | byte |
| FRAMERS_KIT_BITMASK_SIZE | PlayerState.IsFramersKitUnlocked | bit |
| UNLOCK_BITMASK_SIZE | UIState.SetUnlockLinkValue (setter) | byte_masked |
| ACTIVE_HELP_BITMASK_SIZE | UIState.AnnounceHowTo (announce) | byte_masked |
| TRIPLE_TRIAD_NPC_BITMASK_SIZE | UIState.IsTripleTriadNpcBeaten | byte |
| CONTENT_ROULETTE_ARRAY_SIZE | ContentRoulette.CanGetAwards | byte |
| MAPS_WITH_UP_TO_16_REGIONS_ARRAY_SIZE | MapDiscoveryManager.ReadDiscoveryListPacket | byte |
| MAPS_WITH_UP_TO_32_REGIONS_ARRAY_SIZE | MapDiscoveryManager.sub_14085EF00 | byte |

Note: for CONTENT_ROULETTE and the two MAPS_ keys, `unit=byte` means "direct element count" (the guard
tests a plain array index `< K`, no `>>3` shift), not the bitmask `index>>3 < K` form.

Note: these sizes drive both the wire layout (`#[br(count)]`/`#[bw(pad_size_to)]` in the zone server
IPC) and the DB bitmask width (`Bitmask<N>`/`QuestBitmask<N>` in `servers/world/src/database/models.rs`
are const-generic off the constants), so a value change here changes the packet field length and the
saved column width — intended.

## D — manual client-fixed (NOT auto-generated)

Fixed by the client with no inline bound the IDA tool can key off (no bitmask / global byte arrays via
a shared `IsUnlockBitSet` helper / content arrays indexed by id−offset with fixed slack), OR a client
bound that is real but backs frozen/discontinued content, so auto-extraction is pure liability.
Maintained by hand.

- COMPLETED_LEGACY_QUEST_BITMASK_SIZE (=39) — FFXIV 1.x quest completion flags. The client's
  `IsLegacyQuestComplete` bound (39 bytes = 312 bits) is a permanent historical cap: 1.0 content is
  discontinued and complete, so it never grows. Pinned manually instead of kept as a T2 pattern that
  could fail-fast the whole tool for a dead constant. (Value originally extracted via `(a2>>3)<0x27`.)
- UNLOCKED_FISHING_SPOTS_BITMASK_SIZE
- CLASSJOB_ARRAY_SIZE
- AVAILABLE_CLASSJOBS
- BEGINNER_TRAINING_ARRAY_SIZE
- DUNGEON_ARRAY_SIZE, RAID_ARRAY_SIZE, TRIAL_ARRAY_SIZE, GUILDHEST_ARRAY_SIZE, FRONTLINE_ARRAY_SIZE,
  CRYSTALLINE_CONFLICT_ARRAY_SIZE, MASKED_CARNIVALE_ARRAY_SIZE, MISC_CONTENT_ARRAY_SIZE,
  SPECIAL_CONTENT_ARRAY_SIZE
